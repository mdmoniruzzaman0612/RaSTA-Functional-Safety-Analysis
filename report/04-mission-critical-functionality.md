# 4 Mission-Critical Functionality

## 4.1 Introduction

Mission-critical functions are system functions whose failure may result in unacceptable operational, financial, environmental, or safety consequences [8]. In railway systems, communication functions become mission-critical whenever incorrect communication can contribute to hazardous system behaviour [4].

According to IEC 61508, hazards must first be identified and assessed before safety functions can be defined [1]. Similarly, EN 50126 requires a systematic approach to hazard identification, risk assessment, and risk reduction throughout the railway system lifecycle [3].

The objective of this section is to:

* Identify communication hazards
* Assess communication risks
* Derive safety functions
* Establish traceability between hazards and safety mechanisms
* Identify mission-critical protocol functions

The analysis is performed for the RaSTA communication architecture introduced in Section 2 and the requirements defined in Section 3.

## 4.2 Hazard Identification

EN 50159 identifies several communication threats that must be considered when transmitting safety-related information over communication networks [5].

The following communication hazards are considered within the scope of this project.

### H1 – Message Corruption

**Description**

A transmitted message is modified during transmission due to communication errors.

**Potential Causes**

* Electromagnetic interference
* Network hardware faults
* Software defects
* Data corruption within transmission equipment

**Potential Consequences**

* Incorrect control commands
* Incorrect railway status information
* Unsafe system operation

**References:** [5][6]

---

### H2 – Message Loss

**Description**

A message generated by the sender never reaches the receiver.

**Potential Consequences**

* Missing commands
* Missing safety information
* Loss of operational synchronisation

**References:** [5]

---

### H3 – Message Duplication

**Description**

A message is received more than once.

**Potential Consequences**

* Repeated execution of commands
* Inconsistent application state

**References:** [5][6]

---

### H4 – Message Insertion

**Description**

A message appears at the receiver although it was not transmitted by the legitimate sender.

**Potential Consequences**

* Unintended command execution
* Invalid system state transitions

**References:** [5]

---

### H5 – Incorrect Message Sequence

**Description**

Messages arrive in a different order than originally transmitted.

**Potential Consequences**

* Incorrect interpretation of railway system state
* Invalid command execution

**References:** [5][6]

---

### H6 – Excessive Transmission Delay

**Description**

A valid message arrives after its information is no longer valid.

**Potential Consequences**

* Execution of outdated commands
* Delayed operational response

**References:** [5]

---

### H7 – Communication Interruption

**Description**

Communication between protocol endpoints is lost completely.

**Potential Consequences**

* Loss of supervision
* Loss of control information
* Entry into fail-safe mode

**References:** [5][6]

---

### H8 – Masquerading

**Description**

A communication partner falsely presents itself as another valid system.

**Potential Consequences**

* Unauthorized communication
* Unsafe command acceptance

**References:** [5]

## 4.5 Safety Function Derivation

According to IEC 61508, safety functions are introduced to reduce identified risks to an acceptable level [1].

### SF-1 Message Integrity Protection

**Purpose**

Detect message corruption before application delivery.

**Mitigates**

* H1

**Implementation**

* CRC verification

**References:** [5][6]

---

### SF-2 Sequence Supervision

**Purpose**

Detect missing, duplicated, and incorrectly ordered messages.

**Mitigates**

* H2
* H3
* H5

**Implementation**

* Sequence numbering

**References:** [6]

---

### SF-3 Time Supervision

**Purpose**

Detect excessive communication delays.

**Mitigates**

* H6

**Implementation**

* Timing supervision

**References:** [5][6]

---

### SF-4 Connection Supervision

**Purpose**

Detect communication interruptions.

**Mitigates**

* H7

**Implementation**

* Heartbeat monitoring
* Connection state management

**References:** [6]

---

### SF-5 Endpoint Validation

**Purpose**

Ensure communication only occurs with valid communication partners.

**Mitigates**

* H4
* H8

**Implementation**

* Connection establishment procedures

**References:** [5][6]

---

### SF-6 Safe-State Activation

**Purpose**

Prevent unsafe system behaviour when communication validity cannot be guaranteed.

**Mitigates**

* All hazards

**Implementation**

* Fail-safe application response

**References:** [1][4]

## 4.7 Mission-Critical Functions

Based on the hazard analysis, the following protocol functions are classified as mission-critical.

| Function               | Classification       |
| ---------------------- | -------------------- |
| CRC Verification       | Safety-Critical      |
| Sequence Supervision   | Safety-Critical      |
| Time Supervision       | Safety-Critical      |
| Connection Supervision | Safety-Critical      |
| Endpoint Validation    | Safety-Critical      |
| Safe-State Activation  | Safety-Critical      |
| Diagnostic Logging     | Reliability-Critical |

Failure of any safety-critical function may significantly reduce the ability of the communication system to detect hazardous communication failures.

Therefore, these functions require dedicated architectural support, verification activities, and safety justification throughout the remainder of this report.

## 4.8 Section Conclusion

The hazard analysis identified eight major communication hazards relevant to safety-related railway communication systems. Risk assessment demonstrated that several hazards possess High or Very High risk levels and therefore require dedicated safety mechanisms [5][10].

Six safety functions were derived to mitigate the identified hazards. These safety functions establish the foundation for the RaSTA architecture presented in the next section and provide the necessary traceability required by Functional Safety and RAMS standards [1][3][4].
